# Adversarial Seam Review — Architecture Spine zhvi VietPhrase-only

**Verdict: FAIL — spine chưa đủ kín để làm build substrate.**

Các AD đúng về hướng đi nhưng chưa đóng các seam giữa state, artifact, scope và activation. Hai implementation có thể tuân nguyên văn từng AD mà vẫn tạo output khác nhau, mất promotion, dùng nhầm revision hoặc không resume được.

- **[P0] Global state có thể split-brain giữa các book project.** Full design đặt `state.sqlite3` trong từng `book-project/.zhvi/`, nhưng `AutoVietPhrase.txt` và global promotion lại dùng chung toàn repo. Implementation A lưu global evidence/promotion trong DB của book A; implementation B làm tương tự trong DB của book B. Cả hai đều tuân AD-4, AD-7, AD-8 và global lock, nhưng khi lần lượt lấy lock chúng có thể build từ hai snapshot state độc lập rồi ghi đè artifact chung, làm mất promotion của nhau. Spine phải chỉ định đúng một global state store/catalog, khóa ở transaction nào, khóa bảo vệ version nào, và CAS theo `base_global_revision_id`; book DB chỉ được tham chiếu global revision chứ không sở hữu nó. Tham chiếu: spine AD-7/AD-8 và full design §§8, 9, 12.

- **[P0] Pin `dictionary_revision_id` chưa bảo đảm dictionary bất biến.** Implementation A coi revision là manifest trỏ tới các file đang có ở `crawler/vietphrase/dicts/`; implementation B snapshot toàn bộ bytes vào một content-addressed bundle. Cả hai có thể gọi revision “ready/frozen” theo AD-3, nhưng sau khi `Custom.txt`, `VietPhrase_*.txt`, `glossary.auto.tsv` hoặc well-known `AutoVietPhrase.txt` đổi, A sẽ resume run cũ bằng bytes mới còn B dùng bytes cũ. Layout hiện chỉ nêu `dict-<sha256>.manifest.json`, không nêu immutable payload. Spine phải quy định revision là bundle tự chứa hoặc manifest bắt buộc resolve mọi layer tới immutable blob có hash đã verify; TRANSLATE tuyệt đối không đọc mutable well-known path. Tham chiếu: spine AD-3/AD-8/AD-11; full design §§4, 7–9, 12.

- **[P0] Protocol build/materialize/activate không atomic qua SQLite và filesystem.** Convention “append event trước → materialize atomically → activate” vẫn để hở hai crash window. Implementation A rename `AutoVietPhrase.txt` rồi crash trước DB commit: reader theo path thấy dictionary chưa active. Implementation B commit promotion event rồi crash trước rename: DB tuyên bố state không có artifact tương ứng. Cả hai tuân thứ tự mô tả và dùng atomic rename. Cần protocol cụ thể: stage vào path content-addressed không visible, fsync file và directory, verify, commit revision row + activation CAS trong SQLite, rồi chỉ expose bằng pointer có recovery idempotent; hoặc bỏ hoàn toàn mutable path khỏi read path. Phải định nghĩa orphan recovery và invariant DB row ↔ blob hash. Tham chiếu: spine AD-8, consistency convention Mutation/Errors; full design bước 7 và §12.

- **[P0] `ready` và `active` chưa có một nghĩa duy nhất.** AD-4 cho phép TRANSLATE đọc revision `ready`; full state machine lại có `ready → active`, CLI `--no-learn` dùng “active hiện tại”, còn happy path “learn → freeze revision → translate” không nói có activate hay không. Implementation A dịch bất kỳ ready revision được pin; implementation B chỉ dịch unique active revision. Cả hai phù hợp một phần tài liệu nhưng cho kết quả khác khi có nhiều ready revision hoặc concurrent promotion. Cần định nghĩa scope của activation (global, book, hay composed), cardinality “một active mỗi scope”, lệnh nào activate, activation có bắt buộc với explicit revision hay không, và CAS từ expected predecessor. Tham chiếu: spine AD-3/AD-4/AD-13; full design §§6, 8, 10, 12.

- **[P1] Manual ownership xung đột với SQLite ownership và correction path.** Implementation A coi `glossary.manual.tsv` là nguồn chân lý do người sửa trực tiếp rồi importer ghi audit event; implementation B cho `zhvi terms accept` ghi event trước và materialize lại file. A phù hợp “human-owned file”; B phù hợp “append event trước” và SQLite source of truth. Khi file bị sửa ngoài CLI, hai implementation sẽ khác nhau về revision, provenance và overwrite policy. Spine phải định nghĩa manual file là authoritative input hay projection, cơ chế ingest/snapshot, actor attribution, cách xử lý edit ngoài luồng, và xác nhận machine process nào được phép ghi file khi hành động do người dùng khởi tạo. Tham chiếu: spine AD-2/AD-5/AD-8; full design §§4, 7, 8, 10.

- **[P1] Canonical entry identity/grammar chưa đủ để bảo đảm cùng revision.** `source=target`, UTF-8, NFC và “source giản thể để index” không định nghĩa escape cho `=`, newline/comment/BOM, trim policy, pattern namespace, target punctuation normalization version, hay collision khi nhiều traditional forms chuẩn hóa về cùng simplified key. Implementation A split ở dấu `=` đầu; implementation B split ở dấu cuối; hoặc A conflict trên raw source còn B conflict trên normalized source. Cả hai vẫn nói dùng format và NFC nhưng tạo trie/hash khác. Cần canonical DB schema và wire grammar, semantic key `(kind, scope, normalized source/pattern, context)`, normalization algorithm có version, cùng duplicate/conflict rule sau normalization. Tham chiếu: spine AD-5/AD-9 và consistency Entry format/Conflict; full design §§4–6, 13.

- **[P1] Cache key thiếu translation config/policy digest được chuẩn hóa.** AD-11 liệt kê source hash, revision, parser, renderer và QA version; full config còn `style`, `pattern_rules`, `collapse_repetitions`, `qa_strip_junk`, trad-simp map và các field có thể đổi segmentation/render. Implementation A coi `renderer version` là version code, implementation B nhúng toàn config vào đó. Cả hai tuân câu chữ nhưng A có thể trả cache cũ khi đổi style hoặc pattern flag. Cache contract phải chứa explicit `translation_config_hash`, engine/schema version, normalization/trad-simp artifact hash và render policy; learning-only config không nên vô tình làm invalid block cache nếu không đổi revision. Tham chiếu: spine AD-11 và convention Config; full design §§10–13.

- **[P1] Book/global composition không có revision identity rõ ràng.** Implementation A tạo một book revision chứa snapshot global + book auto + manual; implementation B lưu `book_revision_id` chỉ cho book layer và resolve `active_global_revision_id` lúc translate. Cả hai có thể nói run pin “dictionary revision”, nhưng B đổi output khi global revision active thay đổi. Spine phải định nghĩa revision ID là hash của toàn bộ ordered layer set, hoặc pin tuple đầy đủ `{base, global_auto, book_auto, manual_global, manual_book, rules, config}`; manifest/output/cache phải mang cùng composite identity. Tham chiếu: spine AD-3/AD-5/AD-8/AD-11; full design §§4, 6–9.

- **[P1] Cross-book evidence chưa có identity và closed-world semantics.** “Ít nhất 3 truyện độc lập” và “không conflict manual ở bất kỳ project đã đăng ký” không định nghĩa book identity, clone/dedup, project registration lifecycle hay chuyện gì xảy ra khi một project mới có manual conflict. Implementation A đếm ba đường dẫn khác nhau của cùng source; implementation B dedupe theo source hash. Cả hai có thể báo cross-book evidence nhưng một bên promote sai. Cần stable `book_id/source_revision_id`, dedup rule, corpus membership snapshot gắn vào evaluation, và policy cho conflict xuất hiện sau promotion (local shadow, revoke global, hay re-evaluate). Tham chiếu: spine AD-7/AD-14; full design bước 5–6 và milestone 4.

- **[P1] “Affected blocks chứa key” không đủ cho alias và pattern.** Implementation A index raw source substring; implementation B index simplified normalized spans và rule matches. Với key giản thể xuất hiện dưới dạng phồn thể, hoặc `LuatNhan`/pattern tác động theo context, A có thể kết luận diff ngoài affected set và reject, còn B accept; cả hai vẫn dùng source index/trace. Cần định nghĩa impact set theo matcher semantics trên normalized source snapshot, bao gồm alias expansion, pattern context window, overlap/longest-match displacement và versioned index. Gate phải so actual trace diff với predicted superset, không chỉ raw substring. Tham chiếu: spine AD-9/AD-14; full design §§5–7, 13.

- **[P1] Block commit và run-level QA có state machine không tương thích.** Full design yêu cầu block chỉ committed khi output, trace và QA metadata cùng transaction, nhưng QA còn kiểm tra đủ/thứ tự block, entity consistency và output manifest — chỉ biết sau khi toàn run hoàn tất. Implementation A commit block sau structural QA rồi chạy global QA; implementation B giữ mọi block provisional đến cuối. Cả hai hợp lý nhưng resume/visibility/cache khác nhau. Cần tách rõ `block_rendered → block_structural_validated` và `run_validated → exported`, định nghĩa cache chứa artifact nào, và không gọi block “committed/final” trước run gate. Tham chiếu: spine AD-10/AD-11; full design bước 8–9 và §12.

- **[P1] Tie-break bằng `entry_id` chưa ổn định qua rebuild/rollback.** Implementation A cấp UUID mới cho mỗi `ENTRY_VERSION`; implementation B dùng hash semantic của entry. Cả hai đáp ứng “tie-break cố định theo entry_id” trong một revision, nhưng rollback tạo revision mới “tương đương” có thể đổi ID và vì vậy đổi match/output. Spine phải định nghĩa stable semantic entry ID độc lập revision, hoặc tie-break trực tiếp bằng canonical tuple có thứ tự byte rõ ràng; entry version ID chỉ dùng provenance. Metamorphic rollback test phải kiểm tra output hash, trace semantic và entry identity policy. Tham chiếu: spine AD-9/AD-12 và convention ID; full design §§5, 8, 13.

- **[P2] Revision hash và output reproducibility chưa chỉ rõ boundary bytes.** Implementation A hash manifest JSON theo serializer/canonicalization riêng; implementation B hash concatenated dictionary files; đều dùng SHA-256 và có thể gọi là content/revision ID. Khác line ending, file order, JSON key order hoặc timestamp sẽ tạo revision ID khác cho cùng semantics; ngược lại hash chỉ entry set có thể bỏ sót rule/config làm output khác với cùng ID. Cần canonical revision digest spec: ordered logical records, hash của từng external artifact/rule, normalization/config schema version, và canonical serialization không chứa metadata không-semantic. Tham chiếu: spine AD-3/AD-11 và convention ID/Config; full design §§6, 8, 13, 17.

- **[P2] Error recovery chưa quy định reader behavior khi artifact hỏng hoặc thiếu.** Implementation A thấy active row nhưng missing/corrupt trie thì rebuild từ mutable files; implementation B fail closed. Cả hai có thể giữ active revision không đổi, nhưng A có thể silently đổi bytes trong run cũ. Cần invariant read-time verify manifest/blob hashes, fail closed nếu immutable payload thiếu, recovery chỉ rematerialize từ authoritative revision snapshot rồi verify cùng hash; không rebuild old revision từ current mutable inputs. Tham chiếu: spine AD-3/AD-8/AD-11; full design §§6, 12.

## Điều kiện để đổi verdict

Spine chỉ nên chuyển sang PASS khi: (1) khôi phục đầy đủ các AD bị mất; (2) định nghĩa authoritative stores cho global/book/manual; (3) revision trở thành composite immutable bundle; (4) có protocol stage/validate/CAS-activate/recover; và (5) khóa canonical entry, cache, impact-set cùng run state machine bằng contract kiểm thử được.
